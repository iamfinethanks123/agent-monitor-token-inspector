# 時間分析 Dashboard

用量總覽新增 12 個圖表，沿用目前設備、Run、模型同 Project 範圍。圖表有獨立、
共用嘅時間範圍及每格粒度：1、5、15、30 分鐘，1、3、6、12 小時，以及 1 日。
每格粒度唔可以大過圖表範圍；1 日用 1 分鐘粒度會有 1440 格。舊有全歷史每日
圖表亦保留，唔會因為新圖表只睇一日而縮細帳本或刪走歷史。

12 個圖表包括：

1. Token 走勢。
2. Input 與 Output。
3. Output 獨立刻度走勢，避免被較大嘅 Input 壓扁。
4. Cached Input 走勢。
5. Cache 佔已知 Input 比例。
6. 已知未快取 Input。
7. Reasoning 佔已知 Output 比例。
8. 已識別回應與區間記錄數。
9. 已識別回應 Token／分鐘。
10. 設備用量比較。
11. 模型用量分佈。
12. Project 用量分佈。

時間圖表支援滑鼠及左右鍵查看每格確切數字；同一時間游標會同步所有時間
圖表，方便比較。同一輪圖表數據使用同一帳本版本，並顯示確切時間範圍。
排名顯示前八組，另外列明其餘組嘅小計。資料計算用 bigint／字串，圖表座標
才按比例轉成浮點，避免大數量超過 JavaScript 安全整數時改變總數。

Cache 同 Reasoning 係子項，唔會再加進 Total。比例只比較分子同分母都有報告
嘅記錄。未快取 Input 只係有兩個欄位嘅已知部分；未知 Cache 唔會假設為零。
空格代表未有符合範圍嘅帳本記錄，唔代表完整帳戶冇活動。缺少欄位會顯示
未知／部分覆蓋；未知時間嘅先前用量唔會塞入分鐘圖表。

區間用量係按記錄結束時間分配，唔係逐分鐘實際發生時間。Token／分鐘只用
已識別回應同每格時長，唔係模型生成速度。不同設備嘅時鐘唔會用來推斷因果。

真實資料驗證發現舊查詢會先讀取歷史 ledger payload 再檢查 active revision。
在 630053 筆歷史 membership／15527 筆 active membership 嘅檢查點，1440 格
查詢需時 10852 ms。查詢改成先選 active scope，之後同一 revision 772、同一
known total 286941017 嘅查詢需時 795 ms。其他相同模式嘅帳本讀取亦已修正。
呢個係一次真實資料觀察，唔係所有環境嘅效能保證。

針對性測試驗證大於安全整數嘅精確總數、1 分鐘／1 日粒度、1440 格完整性、
模型／設備範圍、Cache 缺少欄位、未知時間同區間唔冒充回應數。原生隔離驗證
會切換時間範圍、粒度同 1440 格，並檢查全部 12 個圖表。正式 App 使用真實
帳本；fixture 數字唔會加入使用者嘅統計。
