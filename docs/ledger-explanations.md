# 帳本成員嘅可追查解釋

用量帳本每筆都有「解釋呢筆用量」。入口依照所點選嘅成員 ID 同不可變帳本
版本，顯示計入／隔離狀態、response／interval／aggregate、模型歸屬、序列
基準、假設、問題、保留來源及截至該快照嘅版本記錄。佢唔會改動帳本或價格。

來源列表唔受 LedgerEntry.evidenceRefs 首 20 筆嘅快捷導航上限限制。透過
ledger_links 每批 50 筆載入全部保留嘅 support／control 關聯，顯示完整數目
同已顯示數目。來源數字係核對證據，唔可以逐行相加；重播份數唔係新請求。
counter 區間嘅兩個端點亦唔係兩筆額外用量。不同回應身份但相同 Token 數
仍然分開計入。

每列顯示記錄設備、來源 ID、generation、行號、byte 範圍、來源時間、
量測類型同保留嘅 Token 欄位。記錄設備未必係最初執行設備；頁面唔會從
相同值、檔案輪替或 Collector 重啟推斷複製／重置。未明原因 counter 下跌
仍隔離；呢個入口冇新增已確認重置、價格修正或負數模型 request 嘅假設。

來源解釋使用 `observation_analyses.revision <= ledger revision` 嘅最新解析，
沒有較早解析時沿用原始不可變 normalized metadata，避免舊帳本同新解析
數字混合。既有 scope 後續更新會列出現行版本，但唔會偷偷改寫點選時快照。
歷史列表只顯示截至點選版本嘅最近 20 個保留版本，附完整保留版本數目；
佢唔係 provider 帳單修正或之後所有變更嘅完整清單。

Cursor 綁定成員／版本、私隱版本、解析 epoch 同來源次序。正常 append
唔會改寫舊成員快照；私隱／重新解析改動會拒絕舊 cursor。來源刪除會移除
相關舊版本及導航資料，唔會由呢個入口復活。私隱通知即時關閉解釋，丟棄
未完成嘅 UI 請求。入口只讀 Metadata；「原始來源預覽」沿用原有 Project
限制同秘密格式遮蔽，「Timeline」定位單一保留證據。

三個針對性回歸涵蓋 73 份重播嘅完整分頁、不同但同量回應、append 後快照、
counter 端點、未知／零分項、矛盾回應歷史、解析版本對齊、cursor 失效及
來源刪除後原始 bytes 不變。隔離原生流程檢查分頁、總數不變、鍵盤操作、
Timeline 及已限制嘅 raw preview。呢啲證據唔代表全規格已完成。
