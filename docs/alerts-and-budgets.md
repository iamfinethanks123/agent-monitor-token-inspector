# 持續異常及資源預算

「分析與建議」保存同一異常嘅更新記錄、證據索引、覆核標記同受控提醒次數。
新來源有 30 秒觀察期；只有最近 10 分鐘嘅新增證據可以提醒，同一異常更新相隔
至少 5 分鐘。提醒只喺 App 顯示，唔會控制 Codex 或發送系統通知。

首次匯入、來源換代、App 重啟時已有嘅記錄會作為基線。歷史發現仍然可以查看，
但唔會當成剛發生嘅異常。來源水位、提醒時間同管理操作會寫入同一 SQLite
交易；中斷或重啟唔會重新送出已記錄嘅提醒。首次提醒之後，只有新證據更新先
可以再提醒；冷卻時間到唔會自己重複提示。

使用者可以將發現標為值得處理、刻意／必要、不相關、不準確或已解決。後四種
標記會抑制該異常嘅提醒。亦可以暫停一個 Run 嘅同類提醒 24 小時；有 Project
篩選時可以對該 Project 暫停。提醒抑制可解除，原始證據同 Token 帳本保持不變。

本機規則包括重複內容、同類執行失敗、至少 256 KiB 嘅已捕捉輸出、五分鐘內
三筆明確壓縮記錄，以及已索引嘅損壞／過大紀錄缺口。壓縮記錄目前未能獨立
證明每筆係不同嘅 provider event；工具輸出同壓縮亦唔會直接轉成節省量。
來源缺口、部分資料、舊證據同未知時間會喺提醒旁邊顯示。

「設定與私隱」可以對目前篩選範圍保存四種獨立預算：

- **Token**：核對帳本嘅已觀察／推導用量，唔包括工具文字估算。
- **未快取 Input**：Input 減已包含嘅 Cache；欄位缺少時保留未知。
- **已記錄時間跨度**：首尾用量時間嘅跨度，唔係實際執行時間，亦唔會相加
  平行 Agent 時長。跨設備時鐘無法比較時顯示未知。介面以分鐘設定、秒顯示。
- **API 等值估算**：只用已覆核價目嘅已知小計；每種貨幣分開，缺價部分列明。
  呢個數字唔係 ChatGPT／Codex 訂閱收費或剩餘額度。

保存時已達門檻、歷史匯入、資料剛由未知變成已知或重新解析，都唔會製造
追溯提醒。已知、近期新增用量跨過門檻時，保存一次 crossing。移除預算只移除
該政策；唔會刪除來源或用量。

Schema 8 加入 incident、source checkpoint 同 suppression 表，保存一致嘅升級前
快照。刪除／到期嘅來源證據會移除相關 incident 副本，亦清除依賴該來源嘅舊
budget snapshot，避免刪除後仍保存用量副本。原始 Codex logs 保持只讀。

針對性驗證涵蓋 100 次重複失敗合併、冷卻更新、持久化重啟、舊資料匯入、
範圍抑制、四種單位、未知 Cache／價格、閾值 crossing、source deletion 同
schema-7 升級。原生隔離驗證會建立兩分鐘預算，檢查保存為 120000 ms，再確認
異常管理介面可開啟；所有呢啲資料都係隔離 fixture。

仍待完成：統計異常嘅可比較歷史 cohort、遠端 Collector transport gap 嘅獨立
提醒，以及無重複 provider-event 證據嘅壓縮識別。現時只提供透明嘅明確閾值，
唔會用未知額度關係預測耗盡時間。
