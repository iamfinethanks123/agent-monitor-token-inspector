# 取消重新解析

規格第18.2節要求重新解析可以取消。「設定與私隱」嘅重新解析執行中會出現「取消重新解析」；取消要求會喺下一個安全核對點生效。切頁或查詢逾時本身唔會取消工作。

每個來源先放入暫存分析，完整核對後先一次過發布。取消未完成來源會清除暫存並關閉檔案，保留上次有效分析；已發布來源保持其新版本。取消唔列為「未能核對」、失敗或成功完成，操作摘要會保留 `cancelled` 狀態、處理人口、已發布／未能核對數同版本，重啟後仍可讀取。工作結束後可以重新解析，正常 scan 亦繼續。

取消 IPC 沿用可信 sender 檢查，要求目前操作 UUID。舊頁面嘅操作 ID 唔可以取消另一個工作。已結束嘅同一操作返回未有取消要求；若最後來源已發布，完成結果優先，唔會回退或虛構未完成來源。UI 等待取消完成期間鎖定取消按鈕，來源／Project／保留政策嘅原有工作鎖保留。

9項 cancellation／進度／privacy 相關測試通過；測試 wrapper 嘅 TypeScript overload 修正後，3項取消測試重跑及最終build／typecheck通過。覆蓋來源之間取消、暫存途中取消、已發布結果保留、暫存清除、原始 bytes 保持、取消後重開及持久摘要。

隔離原生工作流程通過，真實執行20,000個fixture事件嘅核對，UI取消、錯誤操作ID拒絕、取消結果切頁／重啟保留、再執行至完成，以及24-token帳本保持。呢個係功能驗證，唔係真實用戶歷史重新解析、完整resource target或p95測試。原本完成／未能核對／中斷流程亦保持。

冇自動取消用戶嘅實際工作，亦冇為驗證而再啟動大型真實歷史解析。源檔、憑證、帳戶、價目及用戶保留政策維持；headless client唔需要為desktop取消按鈕重新部署。
