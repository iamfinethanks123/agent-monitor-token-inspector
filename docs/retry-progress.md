# 重試同診斷進度

「分析與建議」分開顯示相同失敗反覆出現、失敗簽名有變、有修改操作紀錄後再試、
仍在執行同其後命令退出碼 0。呢啲係已記錄過程，唔會自動評定浪費、任務成功
或可避免成本。缺少可比較簽名唔代表冇重試；遠端統計沒有工具內容。

命令及失敗用已保護指紋比較，原文／路徑唔會放入進度結果。相同 Call ID 嘅
同一設備／Thread 來源副本合併；有衝突或跨來源 generation 配對嘅操作排除。
同一來源、generation、Context epoch 內，以十分鐘觀察窗口組織過程。缺少時間
會保留限制，唔建立已核實執行時長。

已識別程序 handle 嘅輪詢更新同一個嘗試，唔會製造新失敗執行。Handle 用
workspace 指紋保護，按來源範圍連結；缺少指紋或連結嘅輪詢／等待另計。
只接受已知 JSON／literal wrapper，唔執行 trace code 或求值任意表達式。

退出碼 0 只表示命令成功，不代表整套測試、業務正確性或任務驗收通過。
修改表示有相應工具操作紀錄，唔係已驗證 Repository 內容有變。新失敗簽名
可能係有進展嘅診斷訊號，但唔自動給品質分數。修改或簽名變化後，連續失敗
重新計數；同一失敗再次達三次，會恢復候選警示。後續成功保留歷史發現並
抑制提醒，唔係刪除失敗證據。

關聯用量只連結目前已選擇 response 成員、支援觀察落喺同 generation/thread
嘅已配對嘗試範圍內，並取成員聯集。Counter、aggregate、interval 同被隔離成員
唔會分配到嘗試。輪詢延伸同一嘗試嘅可見範圍，但唔會將全部後續 Input
當成因果重試成本。可避免用量保持未知。

最多展示 200 個過程及每組最後 50 個嘗試，計數仍然涵蓋已識別過程；關聯用量
只覆蓋展示範圍，會標示限制。JSON／Markdown 報告保存 metadata 進度，沿用
既有 Project 匯出權限、凍結預覽及遮罩。Scope、刪除、到期由現有工具索引
及資料權限決定，沒有新增原文副本、帳戶操作、Collector 傳送資料或自動 Codex 行動。

Schema 11／wire-v2 不變。既有索引沒有新 process handle metadata 時可以用現有
明確重新分析流程補齊，唔會自動重讀原始內容。
